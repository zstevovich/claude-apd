# Profiles after Opus 5 — decision record

2026-07-25. Draws the line under a day of measurement. Records what was decided,
what it cost, and — deliberately — what is still unmeasured.

## The matrix

```
burn|default|claude-opus-5|max
burn|adversarial|claude-sonnet-5|max
burn|supervisor|claude-opus-5|max

cruise|default|claude-opus-5|high
cruise|adversarial|claude-sonnet-5|max
cruise|supervisor|claude-opus-5|max

eco|default|claude-sonnet-5|xhigh
eco|adversarial|claude-sonnet-5|max
eco|supervisor|claude-opus-5|max
```

No `reviewer` rows: `code-reviewer` keeps its template pin `claude-opus-5 / max`
under every profile.

| role | burn | cruise | eco |
|---|---|---|---|
| builders | opus-5 / max | opus-5 / high | sonnet-5 / xhigh |
| code-reviewer | opus-5 / max | opus-5 / max | opus-5 / max |
| adversarial | sonnet-5 / max | sonnet-5 / max | sonnet-5 / max |
| supervisor | opus-5 / max | opus-5 / max | opus-5 / max |

## Two rule changes, not just values

**Precedence.** A missing role row means "this profile does not mention that
role", so the agent keeps its template pin. It never means "reset to the default
row". Previously only `supervisor` behaved this way; `reviewer` fell back to
`default`, which silently stripped `code-reviewer` off its `effort: max` the
moment any profile was applied — a profile default overriding a deliberate
template value is backwards, and the trap would have repeated for every role
added later. Unnamed agents still resolve to `default`, otherwise "leave it
alone" would turn profiles into no-ops.

**Topology.** Every profile carries a supervisor row. Which roles run is the
shape of the pipeline and must be constant; a profile decides only what each
role costs. While row presence doubled as supervision on/off (v6.30: eco only),
eco and burn were not one pipeline at two prices but two different pipelines —
cross-profile telemetry was not comparable, and drift analysis could not
separate "worse because the model is cheaper" from "worse because a layer never
ran". If supervision ever needs switching off, that must be an explicit flag.

## Why Fable left the agents

Measured cost per dispatch across the corpus:

| class | model | disp | $/disp |
|---|---|---|---|
| builder | **fable-5** | 46 | **71.80** |
| review | opus-5 | 14 | 46.95 |
| builder | opus-5 | 40 | 41.27 |
| supervisor | fable-5 | 58 | 20.48 |
| builder | sonnet-5 | 252 | 18.78 |

The burn builder default was the single most expensive line in the table.
Anthropic puts Opus 5 at max effort within 0.5% of Fable 5's peak CursorBench
score at half the cost per task, priced identically to the model it replaced
($5/$25). Fable stays available on demand and as an orchestrator choice; it is
not an agent default.

Note the supervisor was NOT the expensive item it was assumed to be — $20.48
against $41.27 for one opus-5 builder dispatch, because it makes one focused
pass (26–34 turns) against a builder's 50–77. The argument for fixing the
topology is comparability, not cost.

## What this costs

An eco run goes from roughly $152 to roughly $200: `code-reviewer` stops being
dragged to the builder tier, and the supervisor moves from fable to opus-5.
That is the price of the two rule changes, stated rather than discovered later.

## The measurement that started it

Agents carrying the bare alias `model: opus` were served `claude-opus-4-8`
through 2026-07-23 and `claude-opus-5` from 2026-07-25 — same config, no diff,
nothing recorded anywhere in APD. Across that boundary the median completed run
on one project went from 63 to 104 minutes. Nobody chose it and no APD artefact
could show it.

Three consequences, all shipped:
- every model APD ships or repairs is pinned to a full id, guarded by tests in
  the conf, in shipped templates, and in `apd-init`'s repair path
- `apd report turns` reports the SERVED model per agent and flags an agent that
  ran under more than one model in the window
- `pipeline-metrics.log`'s `model` column is documented as the ORCHESTRATOR's
  model, which cannot answer a profile question

## Still unmeasured — on purpose

The effort values are the least evidenced part of the table.

- `cruise` at `high` vs `xhigh`
- `eco` at `high` vs `xhigh`
- what Opus 5 at `max` actually costs per task — there is not one `max`
  dispatch in the corpus

Related open contradiction: Anthropic reports a user seeing roughly a seventh of
the reasoning tokens versus Opus 4.8, while this corpus measured opus-5 at 77
median turns / 528s per dispatch against 52 / 371s. Most likely an effort-level
difference (those were `xhigh`), unresolved either way.

Measure with `apd report turns`. None of these is decidable by a test.

## Not decided

- whether `eco` should drop to `high`
- whether supervision needs an explicit off switch now that row presence no
  longer provides one
- Codex: supervision cannot dispatch a CC supervisor, so hybrid Codex projects
  now warn on every profile rather than only on eco. Under the current `warn`
  rollout this blocks nothing, but it widens the known strict-flip blocker.
