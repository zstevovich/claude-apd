02 / 14
Problem

LLM piše kod.
Ko proverava da je proces ispoštovan?

Svaki tim „ima proces":
spec → plan → implementacija → review → testovi → commit.
U stvarnosti, kada LLM radi sam, proces je honor system.
Ne postoji mehanizam koji zaustavlja agenta koji:
  • preskoči spec i krene pravo u kod
  • piše tamo gde mu nije dozvoljeno
  • commit-uje bez testova i bez review-a
  • izmeni .done fajl i pravi se da je sve u redu
CENTRALNA HIPOTEZA

Bez mehaničkog

enforcement-a, proces je

samo sugestija.

Konvencija koju slabiji model lošeg dana neće ispoštovati — a ti to nećeš primetiti dok ne pukne u produkciji.

Rešenje

APD = egzoskelet za LLM programera.

Sedmofazni pipeline. 10 guard-ova koji blokiraju svaki pokušaj zaobilaženja. HMAC potpisi na .done fajlovima. Sve preživljava kompaktovanje konteksta, restart sesije i promenu modela.
MEHANIZAM

Enforcement kroz hook-ove

Svaki write, bash i commit prolazi kroz guard koji vraća exit 2 čim otkrije prekršaj. Nema honor system-a.
DISTRIBUCIJA

Plugin, ne framework

/plugin install i sve je tu. Radi na Claude Code i Codexu. Plug-and-play.
DOKAZANO

Brainstorm je obavezan ulaz

  • /apd-brainstorm je mehanički checkpoint pre spec-a
  • Bez marker fajla → spec advance je blokiran
  • Preskakanje samo uz --skip-brainstorm + eksplicitan razlog

Lean vs Full

  • Full (default): svih 5 gate-ova + adversarial prolaz
  • Lean: preskače adversarial samo kada spec ima ≤2 R-kriterija
  • Opt-out je mehanički: adversarial: skip — <razlog> u spec-card-u. Nema tihog preskoka.

Dekontekstualizovani Sonnet adversarial (memory: none) uhvatio je cross-handler bug koji je kontekstualizovani Opus-4.8-max reviewer propustio.

Snaga adversarial-a je u poziciji — nezavisnosti — ne u modelu.
